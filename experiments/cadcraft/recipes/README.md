# CADCraft Recipes v0.1

Библиотека последовательностей черчения для агента. **Не MCP-сервер и не исполняемый workflow.**

Каждый рецепт содержит входные данные, последовательность нативных команд CADCraft (`execute(command, params)`), ожидаемый результат, проверки и переход к следующему рецепту.

## Рецепты

| ID | Задача | Команды | Статус |
|---|---|---|---|
| 01 | Наружные стены | PLINE → OFFSET | Проверено |
| 02 | Г-образная перегородка | PLINE → OFFSET ×2 → ERASE → LINE ×2 → PEDIT JOIN | Проверено |
| 03 | Примыкание перегородки | BREAK основной стены → TRIM граней → BREAK торца | Частично проверено вместе; визуальная приёмка обязательна |
| 04 | Размерные цепочки | SETVAR → DIMLINEAR | Проверено на экспериментальной геометрии |
| 05 | Двойная розетка | ARC/LINE/TEXT → BLOCK → INSERT | Проверено; стандарт символа уточняется |

## Как агент использует рецепты

1. Читает нужный `recipe.md` и `recipe.json`.
2. Подставляет реальные координаты и актуальные handles вместо переменных `${...}`.
3. Выполняет команды **по порядку**, а не весь рецепт одним вызовом.
4. Сохраняет промежуточный DXF и проверяет геометрию.
5. После `BREAK` / `TRIM` повторно определяет handles: CADCraft может заменять сущности.
6. При ошибке прекращает сценарий и сообщает, какая проверка не прошла.
7. После успешного шага читает `next_recipe` и продолжает, если есть необходимые входные данные.

## Важные ограничения

- Исходные обмеры 3565 / 100 / 4717 и текущая экспериментальная цепочка 3520 / 90 / 4772 — **не одно и то же**. Подмена без согласования запрещена.
- `plot fit=true` не гарантирует физический масштаб печати 1:50.
- Розетки пока не имеют динамической привязки к стенам.
- Для реального ремонта требуется сверка размеров, проёмов и конструктивных характеристик.
- Отдельные проверки в CI не равны архитектурной приёмке целого плана.

Существующие исполняемые тесты остаются в `experiments/cadcraft/test_*.py`. Эта папка описывает их как переиспользуемые инструкции.
