# Как добавить элемент в каталог

Элементы полностью управляются данными: палитра, узел на полотне, вращение,
порты и панель свойств — всё читается из каталога. Добавить элемент = **1 иконка
+ 1 строка в реестре + 1 запись в каталоге**. Отдельный React-компонент узла
писать не нужно — все элементы рендерятся через `HydraulicNode`.

## Шаги

1. **Иконка** — `src/shared/icons/XxxIcon.tsx`
   - `viewBox="0 0 48 48"`, `fill="none"`, `stroke="currentColor"`,
     `strokeWidth={2}`, скруглённые концы/стыки.
   - Рисуем инженерный символ (не карточку и не блок).
   - **Заглушки-подводки обязаны доходить до края `viewBox` ровно там, где будет
     порт**: горизонтальный врезной порт по центру → линия на `y=24` до `x=0` /
     `x=48`; нижний порт → линия вниз до `y=48`.

2. **Реестр** — `src/shared/icons/index.ts`: импорт + запись в `iconRegistry`
   под kebab-case-ключом.

3. **Запись каталога** — `src/features/diagram-editor/model/elementCatalog.ts`:
   добавить объект в `elementCatalog`.

## Поля записи каталога

| Поле | Назначение |
|------|-----------|
| `type` | Стабильный машинный id (kebab-case). Он же — полезная нагрузка drag&drop. |
| `label` | Имя в палитре и на узле. |
| `category` | Значение из `ElementCategory`. Новую категорию заводят в `types.ts` + `categories[]`. |
| `icon` | Ключ из `iconRegistry`. |
| `defaultSize` | `{ width, height }` бокса символа в px. |
| `ports` | Точки подключения (см. ниже). |

## Геометрия портов (главное)

- Порты задаются в **локальных координатах бокса**: `x ∈ [0..width]`,
  `y ∈ [0..height]`. `(0, *)` — левый край, `(width, *)` — правый, `(*, 0)` —
  верх, `(*, height)` — низ. Порт обычно лежит **на краю бокса** — туда входит труба.
- Иконка и порты живут в одном боксе, связанном через `viewBox 48×48`:
  `координата_бокса = координата_viewBox / 48 × размер`.
  Значит, заглушка на `viewBox 24` (центр) попадает в `размер/2`; рисуйте
  заглушку до края `viewBox` (0 или 48), чтобы она визуально сошлась с портом.
- `direction` — куда труба выходит из порта (`left`/`right`/`top`/`bottom`).
  Используется для маршрутизации ребра и выбора стороны хэндла React Flow.
- `side` — номинальная сторона (информативно); геометрию считают из `x/y` + `direction`.
- `kind` — `inlet | outlet | solar_supply | solar_return | drain | sensor`.
- `allowedLineTypes?` — ограничение типов линий (id из `lineTypes.ts`).
- `showLabel?` — рисовать подпись порта на узле.

## Общая ось трубопровода (прямые ряды)

Врезные проточные фитинги (кран, насос, фильтр, счётчик, редуктор …) держат
**одну горизонтальную ось**, чтобы ряд оставался прямым:

```
height = 74, левый/правый порты на y = 37
```

Символ центрируем по этой оси (заглушки на `viewBox y=24`). Элементы с
дополнительным вертикальным выносом (нижний дренаж, бак) сохраняют ось `37` для
горизонтальных портов, а остальное продлевают вниз.

> Без общей оси элементы разной высоты соединяются со «ступенькой», и короткий
> фитинг «висит чуть ниже линии». Держите `74 / 37`.

## Вращение — делать ничего не нужно

Задавайте геометрию только для поворота 0. `portGeometry.ts` сам поворачивает
позицию и направление порта, а `getRotatedSymbolSize` меняет местами `w/h` для
90/270. Поворот узла хранится в его данных; кнопка ↻ шагает по 90°.

## Инварианты, которые нельзя нарушать

См. `invariants.md`. Кратко:
- Порты описываются только здесь, в локальных координатах.
- Узел — SVG-символ, а не карточка/блок.
- UI не хардкодит порты и типы линий.
- Хэндл центрируется на точке порта (`transform: translate(-50%, -50%)`).

## Чек-лист

- [ ] Заглушки иконки доходят до краёв `viewBox` в точках портов.
- [ ] Врезной фитинг использует `height 74 / y 37` (если он и правда врезной).
- [ ] `type` и ключ иконки — уникальные, kebab-case.
- [ ] `npm run build` проходит.
